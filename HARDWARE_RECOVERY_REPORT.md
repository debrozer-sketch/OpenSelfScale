# Отчёт: проверка оборудования и восстановления после отказов (волна 11)

Дата: 2026-11-01. Стенд: Debian, киоск на tty1, весы `shtrih-slim` (`/dev/scales` → `/dev/ttyACM0`,
USB CDC-ACM, платформа 0,400 кг), принтер PT-561 (`/dev/ttyS3`, RS-232, 58×40).

Метод: физически недоступные действия выполнялись эквивалентами на уровне драйвера ОС
(unbind/bind интерфейса USB `1-4.1:1.0` через sysfs — реальное исчезновение/появление
устройства для процесса; это не имитация внутри программы). Там, где требуется физический
доступ (питание принтера, кабель RS-232, бумага), сценарий помечен честно.

## 4. Внесённые изменения

Дефектов в драйверах/протоколах/восстановлении не обнаружено. Добавлено:

1. CLI `--print-test` (print.rs `print_test_label_cli`, cli.rs, main.rs): печать тестовой
   этикетки при остановленном киоске — полный путь print_job: предпроверка статуса, печать,
   ожидание фактической выдачи в лоток (открытие порта успехом не считается). Инструмент
   поддержки для проверки железа без интерфейса.
2. Автотест S12: потеря связи с весами при открытой карточке — покупка блокируется,
   восстанавливается без потери контекста.

## 5. Оставшиеся ограничения

1. Физические действия с принтером (питание, кабель, бумага, повторная печать через тач-экран)
   требуют рук на месте — отмечены «не проверен/частично».
2. RS-232: порт монопольно держит демон киоска; CLI-диагностика принтера (`--label-probe`,
   `--print-test`) — только при остановленном киоске (ошибка «Unable to acquire exclusive lock»
   при active-киоске — признак занятого порта, не аварии).
3. Отказ «выключен принтер» имитируется отсутствием ответа; реальная пауза write в ОС-буфер
   не воспроизводится без железа.
4. GS r / ESC v на PT-561 противоречивы (0x03 при бумаге) — в коде не используются как
   критерий; полагаться не стоит и в будущем.
