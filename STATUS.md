## UI (экраны main.slint)
- Статус-полоса (верхние 20px, на всю ширину) — сводный индикатор исправности: светло-зелёная — всё работает; персиковая — этикет-лента заканчивается/закончилась; ярко-красная — критично (нет связи с весовым модулем или принтер не отвечает). В покое текста нет; в проблеме — краткая причина («нет связи с весовым модулем», «принтер не отвечает», «этикет-лента закончилась»); поверх — сообщения печати. Источники: scales-ok = port_up из weight-потока; принтер — фоновый опрос статуса (DLE EOT 4) раз в 10 с, порт с печатью делит через print::port_lock; опрос отключается [printer].enabled=false (стенд).

## Синхронизация
- Режим приёма «как старое ПО» (protocol = "drop" в [center]): сервер магазина сам пушит plu.xml/layout.xml/ready.flg в /var/ftp/scale (FTP-сервер весов), lftp-зеркало — картинки <PLU>.jpg. Киоск опрашивает incoming_dir каждые 5 с, триггер — ready.flg (+ уважает uploading.flg), ждёт стабильности plu.xml (защита от гонки флага и данных старого конвейера), применяет к БД, копирует картинки в img_local_dir/plu, архивирует XML в history_dir, подчищает каталог. --sync в drop-режиме = один проход приёмника. Проверен живой цикл: пуш → обработка → архив → очистка → цена в БД.
- ⚠ TOML: ключи без секции (incoming_dir/db_path/log_file) должны стоять ДО первого [заголовка] — после [printer] они попадают в секцию и молча заменяются дефолтами (был баг: киоск смотрел /home/scales/incoming вместо /var/ftp/scale).
- Права: /var/ftp/scale — administrator:scales 2775 (киоск пишет/удаляет; FTP-юзер добавляется в группу scales); /var/lib/scalefw — administrator:scales.
- Альтернатива (pull): [center] protocol="ftp" + host/... — киоск сам забирает по FTP. Не используется.
- Печать этикетки — только по обычной цене (скидочная в чек пока не заведена).
