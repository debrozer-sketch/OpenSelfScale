# OpenScale — весы самообслуживания нового поколения

Замена устаревшего ПО `SelfServiceScales` (Ubuntu 16.04, Qt5, 2017) на стеке
Rust + Slint. Полная ревизия старой системы — в `audit/`:
- `audit/AUDIT.md` — железо, ОС, ПО, конвейер данных, выводы;
- `audit/PROTOCOL.md` — протоколы весов (Штрих-М) и принтера (ESC/POS), сняты
  живым дампом strace;
- `audit/PROBLEMS.md` — реестр проблем старого ПО → требования к новому.

## Состав

```
crates/
  drivers-api/   контракты периферии: трейты драйверов, профили устройства
  shtrih-m/      драйвер весов Штрих-М (serial 115200, LRC, опрос массы)
  escpos/        драйвер этикетного принтера ESC/POS (serial 19200, page mode)
  datastore/     SQLite-база PLU, импорт из XML (формат plu.xml старого ПО)
app/
  kiosk/         бинарник киоска: UI (Slint), машина состояний, диагностика
center/          центральный конфигуратор (TypeScript): визуальный редактор
                 этикеток/кнопок, парк весов (скелет)
docs/
  ARCHITECTURE.md  архитектура и решения
  ROADMAP.md       план работ
```

## Конвейер данных (drop-протокол)

Как в старом ПО — источник сам пушит данные на весы, киоск следит за каталогом:

1. Сервер магазина (по cron, как в старом конвейере) кладёт `plu.xml`,
   `layout.xml` и картинки `<PLU>.jpg` в каталог приёма (`[center].
   incoming_dir`, обычно `/var/ftp/scale` — FTP-сервер весов) и ставит
   триггер `ready.flg`. Перед началом заливки — `uploading.flg`.
2. Киоск опрашивает каталог каждые 5 с, ждёт стабильности размеров
   (защита от докачки), импортирует товары и раскладку в SQLite, копирует
   картинки, архивирует исходники в `history_dir`, подчищает каталог.
3. Запасной режим (pull): `protocol = "ftp"` — киоск сам забирает
   выгрузку с центра. Не обязателен.
4. Никаких рестартов на обновление: данные применяются живо.

## Принципы (из PROBLEMS.md)

1. Обычная SQLite, без шифрования и процедур пересоздания.
2. Полный статус-мониторинг принтера и весов (статус-полоса киоска).
3. systemd-супервизия, ротация логов.
4. Один источник правды по товарам — центр; весы только применяют.
5. Платформенная запаска: периферия через драйвер-контракт (drivers-api),
   порты/скорости/тип драйвера — в config.toml платформы; сборка под
   x86_64/aarch64 из одного кода (cargo zigbuild).

## Сборка

```bash
cargo build --workspace      # все крейты
cargo test  --workspace      # тесты драйверов на байтах из реального дампа
```
