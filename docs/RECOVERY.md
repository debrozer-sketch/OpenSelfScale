# Удалённое восстановление и переустановка весов

Цель: любая поломка ПО чинится с центральной машины, без поездки с флешкой.
Работает в три уровня — по степени деградации весов.

## Уровень 0. Переустановка/обновление ПО весов (ОС жива)

Штатный случай: ОС грузится, приложение сломано или нужна новая версия.

- По SSH (или через SFTP-скрипт `deploy/push.py`) заливается бинарник
  киоска, сервис `scale-kiosk` перезапускается, идёт self-test
  (`kiosk --diag`).
- Откат: предыдущий бинарник хранится на центральной машине (или в git —
  сборка воспроизводится из коммита), заливается обратно той же командой.
- Средство: `python deploy/push.py <binary>` + `python scale_ssh.py --sudo
  "install -m755 ... && systemctl restart scale-kiosk"` (см. STATUS.md).

## Уровень 1. Переустановка ОС по SSH (система грузится, но убита)

Случай: разрушена ФС/пакеты/загрузчик приложения, лечится только снос ОС.

1. С центра по SSH (root) заливаются на локальный диск весов:
   `vmlinuz` + `initrd.gz` установщика Debian 13, `preseed.cfg`, золотой
   образ (rootfs-тарболл) — всё с центрального HTTP-сервера.
2. `kexec -l vmlinuz --initrd=initrd.gz --command-line=...` и `kexec -e` —
   установка стартует БЕЗ физического ребута и без правки UEFI.
3. Preseed размечает диск и разворачивает золотой образ (не сетевая
   установка пакетов — их нет, LAN изолирован; всё тянет с центра по HTTP).
4. Первый старт: скрипт enroll — hostname, статический IP из карты парка,
   SSH-ключи, запуск киоска, self-test, heartbeat в центр.
5. `scalectl os reinstall --target scales-N --image v1.2.3` — одна команда.

Занимает минуты (тарболл ~1–2 ГБ по LAN) и не требует присутствия.

## Уровень 2. ОС не грузится вообще (SSD умер, загрузчик снесён)

SSH мёртв, kexec недоступен. Спасает сетевая загрузка BIOS/UEFI:

- У весов RTL8111 — полноценный UEFI PXE. В UEFI порядок загрузки ставится:
  **диск → сеть**. Пока ОС жива, сеть не используется; как только диск не
  стартует — прошивка падает в PXE.
- В LAN магазина постоянно работает центральный бокс: DHCP (обычные
  аренды + опции PXE) и TFTP/HTTP. PXE отдаёт тот же установщик с тем же
  preseed — весы после включения питания чинят себя сами.
- Даже при полностью убитом диске и сбитом NVRAM есть запасной путь:
  fallback `\EFI\BOOT\BOOTX64.EFI` на ESP + PXE.
- Это тот же iVentoy-механизм, который уже есть в арсенале (E:\iventoy),
  только упакованный в штатную инфраструктуру магазина, а не как ручной
  инструмент.

## Что для этого нужно в магазине

| Компонент | Где | Назначение |
|---|---|---|
| DHCP+TFTP+HTTP | центральный бокс LAN | аренды, PXE, раздача образов |
| Хранилище образов | там же | golden-image версии + манифесты |
| Карта парка | центр (БД/файл) | MAC → IP → hostname, версия образа |
| scalectl | центр | deploy / reinstall / статус парка |

## Ограничения и риски

- Обрыв питания посреди установки уровня 1/2 → диск размечен пусто. Не
  фатально: PXE-путь (уровень 2) не зависит от диска — после подачи питания
  установка повторится сама.
- Уровень 2 требует, чтобы в LAN магазина постоянно жил DHCP-сервер. Это
  отдельный сервер или мини-бокс (даже Raspberry Pi достаточен).
- Проверка после восстановления обязательна: heartbeat + diag + пробная
  печать; только тогда парк помечается «в строю».
- UEFI-настройки на конкретной весы проверяются один раз при вводе в
  эксплуатацию (BootOrder: disk → network), дальше не трогаются.

## Открытые вопросы

- В каждом магазине центральный бокс — один на LAN весов? (судя по старому
  конвейеру, сервер 192.168.0.87 уже доступен из сети весов — вероятно, да).
- Удалённое управление питанием (умная розетка) — необязательно: уровни
  0–1 не требуют ребута руками, уровень 2 срабатывает при подаче питания
  охраной/персоналом магазина.
