# Мастер первичной настройки и чек-лист ввода в эксплуатацию

Дата: 2026-10-20
Статус: утверждено (обсуждение в чате, все разделы согласованы)

## 1. Задача

Весы после установки ПО приходят «пустыми»: нет пользователей, сети
под настройки, калибровок, товаров, раскладки этикеток. Мастер
первичной настройки проводит инженера по обязательным шагам один раз;
после мастера динамический чек-лист на экране показывает, чего ещё не
хватает для работы, и закрывается кнопкой «Ввести в эксплуатацию».
Инвариант «программа не зависает» распространяется на мастер: каждый
шаг с ожиданием (калибровки, проверка груза) имеет выход по таймауту и
может быть перезапущен.

## 2. Триггеры и состояния

Состояния хранятся в `app_settings` (TEXT key/value):
- `setup_stage` — номер шага мастера, где остановились (0..8);
- `setup_wizard_done` — мастер пройден (0/1);
- `setup_done` — весы введены в эксплуатацию (0/1).

Триггер мастера: таблица `admin_user` пуста → киоск стартует сразу
в мастере без авторизации. После создания PIN-ов прерванный мастер
открывается по PIN администратора (пункт меню «Продолжить настройку»).

Заводской PIN и `seed()` удаляются: никакого дефолтного пароля нет.
Флаг `pin_changed` (calibration) и его логика удаляются вместе с seed.

`setup_done` и PIN-ы не экспортируются через `cfgio`: это состояние
конкретного устройства, а не настройка для клонирования.

## 3. Роли

- **admin** — полный доступ: все существующие экраны настроек
  («Оборудование», «Отчёты», «Сеть», импорт, калибровки, «Настройки
  весов»).
- **staff (кассир)** — минимальный набор: протяжка этикетки и
  перезагрузка. После ввода в эксплуатацию вход PIN-ом staff открывает
  подменю из двух кнопок (протяжка, перезагрузка) и «Выйти»; остальное
  скрыто.

Пароли: админ — минимум 4 цифры, ввод ×2; кассир — то же, шаг можно
пропустить («Пропустить» → кассирский PIN не создаётся, пункт доступен
позже из меню админа).

## 4. Шаги мастера (строго по порядку, state = advance())

| № | Шаг | Выполнение считается |
|---|-----|----------------------|
| 1 | PIN админа | Два совпадающих ввода ≥4 цифр, записан в `admin_user` |
| 2 | PIN кассира | То же, либо «Пропустить» |
| 3 | Сеть | Существующий экран «Сеть»; шаг закрывается кнопкой «Далее» (DHCP/статик применён или осознанно отложен) |
| 4 | Проверка весов | Авто-критерий: стабильный ноль, затем на платформе груз ≥100 г виден (вес течёт в тик, опросов не добавляет) |
| 5 | Калибровка печати | Тестовая этикетка → оператор: «ок / хвост обрезан / уехало» (логика feed±16 из `calib`, переезд в UI) |
| 6 | Калибровка длины | Шаг-скан (готов); санити <15 мм не сохраняет |
| 7 | Дата/время | Ручной ввод `ДД.ММ.ГГГГ ЧЧ:ММ` через хелпер + переключатель NTP |
| 8 | Финал | `setup_wizard_done=1`, перезапуск киоска |

«Назад» внутри мастера разрешён (перезапуск шага), после финала — нет:
повторный вход в мастер из меню админа не перезапускает пройденное.

## 5. Чек-лист (после мастера, до ввода в эксплуатацию)

Главный экран вместо меню отделов показывает чек-лист; каждый пункт —
живая галка из тика (2 новых поля TickCache: битмаск пунктов, флаг
режима). Пункты:

- **Товары** — в `plucodes` есть записи (синк или импорт);
- **Раскладка этикетки** — `label_layout_name` задан в `app_settings`
  (импорт `label-*.json` — часть движка этикеток, отдельный этап);
- **Принтер** — связь есть, аварии нет (текущие поля здоровья);
- **Весы** — порт отвечает, ноль стабилен.

Все зелёные → активна кнопка «Ввести в эксплуатацию» → `setup_done=1`
→ рабочий режим. Чек-лист остаётся в «Оборудовании» для диагностики
(тот же список, только просмотр).

Оценка пунктов — чистая функция `evaluate(...) -> u32` (битмаск) от
(число PLU, раскладка, здоровье принтера, снимок весов): покрывается
unit-тестами, экранная обвязка — на стенде.

## 6. Дата/время (шаг 7)

- Ручной ввод: клавиатурой `ДД.ММ.ГГГГ ЧЧ:ММ` → киоск вызывает
  `/usr/local/bin/openscale-settime "<значение>"`. Хелпер — root-скрипт с
  жёсткой валидацией (регэксп + диапазоны), внутри
  `timedatectl set-ntp false && timedatectl set-time ...`.
- Sudoers: одна строка
  `administrator ALL=(root) NOPASSWD: /usr/local/bin/openscale-settime`.
  Файлы `deploy/openscale-settime` и `deploy/openscale-settime.sudoers`,
  установка описана в `deploy/README.md`. Других NOPASSWD нет.
- NTP: переключатель «NTP: вкл/выкл» (дефолт — вкл) →
  `timedatectl set-ntp true/false`. Сервер времени — опциональная
  строка `[time] ntp` в `config.toml` (сеть без интернета; пусто —
  debian pool). Выключенному NTP соответствует только ручной режим.

## 7. UI

- Новый полноэкранный этап `setup` (экран 19 в текущей нумерации).
- Вёрстка: заголовок «НАСТРОЙКА ВЕСОВ»; слева — вертикальный список
  шагов (готово ✓ / активен / заблокирован); справа — контент активного
  шага. Переиспользуются: экран клавиатуры PIN, экран «Сеть», кнопки
  калибровок из «Оборудования».
- Чек-лист — те же слоты списка с живыми галками; снизу кнопка
  «Ввести в эксплуатацию» (активна при полном наборе).
- Экраны 4 (меню) и 18 («Оборудование») остаются без изменений; из
  меню админа доступен «Продолжить настройку», пока `setup_done=0`.

## 8. Инварианты «программа не зависает»

- Калибровочные шаги уже имеют дедлайны и ACK-таймауты (150/180 с) —
  переиспользуются как есть.
- Проверка груза (шаг 4) — пассивное чтение тика, без блокировок;
  шаг закрывается оператором.
- Сбой любого шага не блокирует мастер: шаг можно перезапустить,
  мастер — продолжить с `setup_stage`.
- Запись состояния (`.new` + замена в БД) идёт после успешного
  выполнения шага, не до.

## 9. Тесты

- `auth`: создание пользователей мастером без seed; verify admin/staff;
  тесты seed удалены вместе с seed.
- Мастер: `advance(stage, action)` — порядок шагов, пропуск кассира,
  запрет выхода за финал; unit-тесты.
- Чек-лист: `evaluate` — комбинации (нет товаров / нет раскладки /
  принтер в аварии / весы молчат / всё зелёное); unit-тесты.
- Экранная обвязка (Slint, тики, кнопки, хелпер времени) — на стенде.

## 10. Вне рамок (следующие этапы)

- Движок раскладок и импорт `label-*.json` (пункт чек-листа «Раскладка»
  до его появления всегда красный).
- Подбор раскладки по измеренной длине этикетки.
- Сервер/центр обновлений (бэклог).
