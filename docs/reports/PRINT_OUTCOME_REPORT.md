# Отчёт: неопределённый результат печати (волна 14)

Дата: 2026-11-01. Принтер PT-561 (ESC/POS, RS-232), журнал print_log (ok = 1/0/NULL).

## 1. Карта состояний печати (после изменений)

Точки, где результат становится неопределённым, и их классификация:

| Точка пути | Результат | ok в журнале | Сообщение оператору |
|---|---|---|---|
| Принтер выключен в конфиге / вес > лимита (до постановки в очередь) | задание не создавалось | записи нет | — |
| Порт не открылся, ESC @ не прошёл, статус-проверка до отправки (ensure_ready) | достоверная ошибка — байты не отправлялись | 0 | «Не удалось напечатать этикетку. Повторите попытку» |
| Задание устарело в очереди (STALE_JOB) / отменено до отправки | достоверная ошибка | 0 | то же |
| Отказ принтера во время печати (подтверждённый fault L4) | достоверная ошибка — этикетка не в лотке | 0 | то же |
| Ошибка `write_all`/`flush` после начала отправки | **неизвестно** — часть байтов могла уйти | NULL (не маркируется) | «Не удалось проверить печать: этикетка могла выйти…» |
| Датчик лотка не подтвердил выдачу за present_wait без явного fault | **неизвестно** | NULL | то же |
| Киоск не дождался ответа демона (30 с) / демон не ответил (90 с) | **неизвестно** | NULL | то же |
| Датчик подтвердил этикетку в лотке | успех | 1 | «Заберите этикетку» → «Этикетка напечатана» |

Открытие порта и успешная отправка байтов подтверждением печати не считаются:
успех — только по датчику лотка (label_in_tray), что уже было реализовано в волне 11.

## 3. Журнал и повторная печать

- ok=NULL отображается в журнале и в «последних операциях» меткой `?` (было и раньше —
  теперь эта метка честно означает только «результат не подтверждён», а не любую неудачу).
- Неизвестный результат отличим от «не отправлялось»: не отправлялось (порт не открылся,
  устарело, отменено до отправки) → ok=0; начало отправки без подтверждения → ok=NULL.
- Связь повторной печати с исходной: повтор создаёт новую запись с `origin_id`; исходная
  запись не перезаписывается и не удаляется.
- Повтор неизвестной записи — только явное двухшаговое действие оператора (выбор строки →
  диалог подтверждения), для ok=NULL диалог содержит предупреждение о дубликате.
- Автоматических повторов нет (не добавлялись).

## 4. Сохранность после аварии

- kill -9 во время отправки: запись создана до отправки (ok=NULL); daemon не успел
  маркировать → остаётся NULL = неизвестный результат. Задним числом успешной не объявляется.
- kill -9 до постановки в очередь: записи нет (продажа не задокументирована — корректно).
- Перезапуск службы: ok=NULL остаётся ok=NULL (тест `interrupted_print_stays_unknown_after_reopen`).
- Таймаут выдачи / потеря порта после отправки: Uncertain → NULL.
- Отказ до отправки: достоверная ошибка → ok=0.

## 7. Оставшиеся ограничения

1. Exactly-once печать на ESC/POS недостижима: повтор после неизвестного результата может
   дать дубль — предупреждение в диалоге снижает риск, но не устраняет его.
2. Если киоск убит между отправкой задания в демон и записью результата, фаза 5 не
   сохраняется (состояние в памяти) — но запись в БД уже ok=NULL, и оператор увидит `?`
   в журнале после перезапуска. Это соответствуют цели «не задним числом успешная».
3. Датчик лотка PT-561 подтверждает только факт этикетки в лотке: застрявшая посреди
   печати этикетка при валидном L4 классифицируется как успех — ограничение датчика.
