# Отчёт: каталог товаров — производительность и UX (волна 12)

Дата: 2026-11-01. Стенд: x86_64 Celeron J1900 (4 ядра, 1,99 ГГц — слабое одно платное
железо), киоск 1024×768, каталог 218 товаров, синтетика 2000 товаров.

## 1. Разбор текущего поведения (по коду, без догадок)

- Первое открытие каталога: чтение отделов/групп в рабочем потоке (relayout), UI получает
  готовый вектор; товары читаются тем же фоновым путём при refresh_data.
- Открытие отдела: фильтр каталога O(n) + сортировка + `tile_light` без изображений;
  картинки прикрепляются только к видимой странице (show_items_page, кеш 768).
- Поиск: проход по предпостроенному индексу заглавных названий, первые 5 совпадений,
  подсветка — O(n) на клавишу, без блокировки UI.
- Обновление после синхронизации: чтение каталога в рабочем потоке; при открытом каталоге —
  перестройка списка на UI-потоке.

## 2. Найденные проблемы (реальные узкие места)

1. **Обновление каталога после синхронизации грузило изображения всех товаров отдела
   в UI-потоке** (flow.rs: `tiles::tile_of` на каждый элемент). На каталоге из 2000 товаров
   отдел из 2000 позиций → 2000 попыток загрузки картинок на UI-потоке при каждой
   синхронизации при открытом каталоге — заметное зависание на слабом железе. Для 218
   товаров эффект мал, но растёт линейно с каталогом. Исправлено: `tile_light` (как при
   обычном открытии отдела); картинки добавляет show_items только для видимой страницы.
2. **Поиск по коду товара отсутствовал**: индекс содержал только заглавные названия.
   Оператор не мог найти товар по артикулу/PLU. Исправлено: индекс дополнен строкой
   «itemcode plu»; совпадение по названию ИЛИ коду; подсветка — только для совпадений
   по названию (совпадения по коду показываются без подсветки).

Косметика и торговая логика не менялись.

## 3. Замеры на стенде (J1900, release-сборка, UI-тесты Slint testing-бэкенда)

Синтетика 2000 товаров в одном отделе (`OPSCALE_BENCH=1 ui_tests::ui_scenarios`):

| Операция | Время (стенд) |
|---|---|
| Первое открытие каталога (2000 товаров) | 9 мс |
| Повторное открытие | 5 мс |
| Переключение категорий (БЕНЧ → ФРУКТЫ → БЕНЧ) | 4 мс |
| Возврат из карточки товара | 0 мс |
| Поиск, 8 клавиш подряд (по названию) | 4 мс суммарно |
| Поиск по коду («500000») | 1 мс |
| Обновление после синхронизации (на открытом каталоге) | 0 мс |

На Windows-машине разработки (быстрее стенда): открытие 11 мс, поиск 5 мс — согласуется.

Замер «до» для обновления-после-синхронизации на стенде не воспроизводится (код уже
исправлен); проблема подтверждена ревизией: 2000 `attach_image` (дисковый I/O + декодирование
изображений) в UI-потоке против 0 после исправления — выигрыш соответствует объёму отдела.

Также добавлены постоянные замеры в прод-логе: операции дольше 10 мс пишут
`[тайминг] открытие каталога …/поиск/страница товаров/обновление` — заметное замедление
не останется незамеченным в эксплуатации.

## 6. Оставшиеся ограничения

1. Изображения товаров в синтетике нет (файлы отсутствуют) — замер отражает код приложения
   (фильтр/сортировка/модели Slint); стоимость декодирования картинок ограничена видимой
   страницей и кешем — как и раньше.
2. Виртуализация списка не введена: при 2000 товарах перестройка занимает единицы
   миллисекунд — сложный кеш не оправдан измерениями.
3. Поиск ограничен 5 результатами (существующее поведение) — не менялось намеренно.
