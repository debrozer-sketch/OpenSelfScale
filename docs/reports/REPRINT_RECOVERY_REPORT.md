# Повторная печать и восстановление операций — OpenScale

Дата: 2026-10-31. Деплой: sha256 `459200b29407499398eab7bf7253f125468e19a300275cbdd88cd24d7f0b8b56`.

## 1. Проверка журнала (до работ)

`print_log` (datastore): `id, ts, plu, name, weight_g, sum_kop, ok` — только итоги
попытки печати. Полной карточки покупки не было: нет `itemcode` (штрихкод),
`namesecond`, `price`, `shelflife` — повторная этикетка из такой записи
невозможна без каталога. Отчёты (`build_report`, популярность, счётчики)
строятся из этого журнала: `ok=1` — продажа.

После волны fix(trade): `ok` был бинарным (0/1), «попытка прервана крахом»
выглядела как ошибка — требование различать исходы не выполнялось.

## 2. Хранение снимка покупки (миграция)

Схема `print_log` после миграции (совместима со старыми базами, тест
`print_log_migration_keeps_old_rows`):

```
id, ts, plu, name, weight_g, sum_kop,
ok        INTEGER          -- NULL = исход неизвестен, 1 = успех, 0 = ошибка
itemcode, namesecond, price, shelflife,  -- снимок покупки
origin_id INTEGER          -- корневая покупка для повторной печати
```

- Миграция перестраивает таблицу в транзакции, старые записи сохраняются
  (ok остаётся как был, снимок пуст — такие записи неповторяемы).
- Попытка фиксируется с `ok=NULL` до передачи на принтер; демон после
  задания помечает исход (`print_log_mark`).
- Повторные печати в отчётах продаж не считаются (`origin_id IS NULL`
  в `print_popularity` и `print_log_count_since`); фильтр «Ошибки» в
  журнале показывает и прерванные попытки (`ok=0 OR ok IS NULL`).

## 3. Повторная печать

`print::print_reprint(cfg, rowid)` (print.rs):
- этикетка собирается из **снимка** строки журнала (`snapshot_item`):
  товар, наименование, масса, цена за кг, срок, дата и время покупки;
  изменение каталога не влияет на содержание (`reprint_uses_snapshot_after_catalog_change`);
- исходная запись не изменяется; создаётся новая строка-попытка с
  `origin_id` = корень цепочки (повтор от повтора ссылается на исходную
  покупку, `reprint_chain_links_to_root_purchase`);
- те же правила формирования этикетки (`build_label_from_spec`) и
  сериализация через обычный демон печати; попытка помечается исходом;
- защита от параллельных копий: `REPRINT_BUSY` в UI (одна попытка за раз)
  + демон обрабатывает задания последовательно; авто-ретраев нет;
- ошибки: `Reprint("нет снимка")` для старых записей, лимит массы,
  недоступная БД — исходная операция при этом не меняется
  (`reprint_disabled_printer_leaves_log_untouched`).

UI: экран «Отчёты» — список последних операций (`+` продажа, `↻` повтор,
`!` ошибка, `?` исход неизвестен); тап по строке с снимком → подтверждение
«Повторить печать этикетки?» → результат popup. Записи без снимка
приглушены, повтор для них недоступен.

## 4. Восстановление после перезапуска

Автоматических действий при старте нет (требование: не печатать дубликат).
Прерванные крахом попытки остаются `ok=NULL` и отображаются как «исход
неизвестен» (`?`), доступна ручная повторная печать — то самое ручное
решение через существующий интерфейс. Результат печатать-ли решает
оператор, видя фактическое состояние принтера.

## 5. Коммиты и тесты

- `datastore`: схема+миграция, `PrintLogRow` со снимком и `ok: Option<bool>`,
  `print_log_get/recent`, фильтры продаж.
- `print.rs`: снимок при попытке, `print_reprint`, `snapshot_item`.
- `settings.rs`: список операций, confirm-popup, BUSY, отчётные пометки.
- `ui/main.slint`: `ReportOp`, список на экране отчётов, popup повтора.

Новые тесты (183 всего, зелёные): миграция старой базы, снимок roundtrip,
`mark`/неизвестный исход, продажи без повторов, список recent,
снимок после изменения каталога, неповторяемость старой записи,
цепочка повторов, отказ без изменения журнала; release-сборка без
предупреждений.

## 6. Ограничения

- Прерванная передача остаётся «неизвестной» навсегда: был ли напечатан
  физический лист, протокол ESC/POS не сообщает. Решение за оператором.
- Снимок не хранит `price_rounding` на момент покупки: сумма берётся из
  `sum_kop` снимка, но пересчёт этикетки при изменении калибровки
  может дать расхождение в копейках (калибровка меняется редко).
- Старые записи (до миграции) неповторяемы — на этикетках нет нужных полей.
