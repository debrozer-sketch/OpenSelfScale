# Отчёт: эксплуатационная готовность (волна 19)

Дата: 2026-11-01. Заключительная плановая волна. Проверка шести сценариев,
исправление двух найденных дефектов.

## 1. Реально найденные дефекты

1. **Экран «Обслуживание» не различал выключенный в настройках принтер** —
   при `printer.enabled = false` показывалось «нет данных» (как «ещё не
   проверяли»). Оператор ищет неисправность там, где её нет.
2. **Опрос недоступного принтера замусоривал журнал**: после первого сбоя
   `fault_streak` удерживал частый опрос (800 мс), и при выключенном
   принтере каждый опрос писал warn + INFO-замер в append-лог (десятки
   строк в минуту, часами, пока принтер выключен).
3. (Из предыдущего цикла, сюда же относится найденная на стенде причина
   зависания: sudo-хелпер VNC наследовал tty1; при недействительном
   правиле sudoers sudo запрашивал пароль и job-control сигнал
   останавливал киоск. Исправлено: `sudo -n` + null-потоки во всех трёх
   sudo-вызовах; sudoers на стенде отремонтирован; README дополнен
   требованием подстановки `@KIOSK_USER@`. Коммит ea9f182.)

## 2. Что исправлено и чем защищено

- **Принтер «выключен в настройках»** — отдельная строка на экране
  обслуживания (янтарная). Тест: `maint_printer_disabled_is_distinct_from_no_data`.
- **Лог probe — по смене состояния**: warn «опрос статуса принтера» только
  при входе в сбой; «принтер: связь восстановлена» при возврате ответов;
  INFO-замер L4 — только до входа в сбой. Выключенный принтер = несколько
  строк вместо тысяч. Регрессионного теста нет (мок порта невозможен —
  `dyn serialport::SerialPort`), защищено обзором и стенд-проверкой.
- Сценарий 1 дополнительно закрыт существующим механизмом: при включении
  принтера опрос (800 мс при сбое) снимает fault и ставит «готов» без
  перезапуска приложения; экран обслуживания обновляется по кнопке.

- **Тестовая печать с датчиком лотка (CLI-путь, тот же `print_job`)**:
  этикетка напечатана, датчик подтвердил выдачу (`выдана=true`, L4-трасса
  320 мс) — физическое подтверждение волны 18 для PT-561.
- **print_log и продажи**: после тестовой печати `--db-check` показывает
  0 записей печати — статистика не затронута.
- **Весы**: `--weight` отвечает по /dev/scales (платформа пуста: «НЕ
  СТАБИЛЬНО: 0.000», exit 3 — ожидаемо, связь есть).
- **База**: `--db-check` — integrity ok, 218 товаров.
- **Перезапуск**: сервис active, журнал без panic/ERROR.
- **S1–S19**: полный `ui_scenarios` тестовым бинарником на стенде — ok.
- **VNC-toggle**: sudo-хелпер вручную on/off от пользователя сервиса —
  работает без пароля, сервис VNC включается/выключается.

  стендом, а не unit-тестами.
- **cargo clippy не выполнен**: компонент clippy не установлен, загрузка
  недоступна (нет сети на рабочей машине). Тесты и release-сборка — без

- Физический тач-доступ к экрану стенда недоступен — UI-кликабельность
  проверена Slint testing-бэкендом.
