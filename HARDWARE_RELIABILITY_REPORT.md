Волна 5. Дата: 2026-10-31. Стенд: Debian 13, ARM, service `openscale-kiosk`, deploy sha256 `fc182d3d…`.

## 1. Карта взаимодействия с оборудованием

| Компонент | Файл | Граница отказа | Восстановление |
|---|---|---|---|
| Весы | `app/openscale/src/weight.rs` | `open_driver` Err, таймауты ответов (`SILENT_LIMIT = 6`), устаревший снимок (`SNAPSHOT_STALE_MS = 1500`), паника потока | `poll_loop` закрывает сессию, `sleep_interruptible(3s)`, переоткрывает драйвер; состояние сбрасывается (`port_up=false`, вес=0); `WeightSource::Drop` = stop+join (без гонок при выходе) |
| Принтер | `app/openscale/src/print.rs` | `with_port` (переоткрытие при Err), статусы L4: fault (`0x04`), лоток (`0x60`), тишина при ожидании этикетки | `Monitor` с двойным подтверждением (`FAULT_CONFIRM`, `SILENT_CONFIRM`), `probe`, `recover` (сброс/резет), reopen порта; статус сбрасывается при снятии этикетки |
| Сервисные команды (время, VNC, калибровка, тест) | `app/openscale/src/settings.rs` | зависший/долгий дочерний процесс | `run_cmd_timeout(cmd, timeout)`: spawn+try_wait+deadline+kill, panic-safe; BUSY-флаги (`PRN_BUSY`, `VNC_BUSY`) не дают запустить второй сервисный процесс |
| Выгрузка XML (FTP/каталог) | `app/openscale/src/sync.rs` | битые/частично переданные файлы, мусор после `</body>`, не-UTF-8 | `decode_xml`: обрезка по первому `</body>` (мусор кассы дописывает даже обрывок со своим `</body>`); полностью битая кодировка отклоняется с явной ошибкой; повтор цикла каждые 60 с |
| Импорт каталога | `crates/datastore/src/lib.rs` | частично принятая выгрузка | `import_plu`/`remove_absent`/`apply_layout` атомарны каждый; сбой между операциями оставляет частичный каталог до следующей выгрузки |

Локальные торговые операции (взвешивание, печать, отчёты, настройки) не требуют сети: FTP-недоступность влияет только на приём выгрузки, логирование (локальный файл) продолжает работать.

## 2. Дефекты, найденные и исправленные в этой волне

### D1 (P1) Выгрузка не применялась: вложенная транзакция
- Симптом на стенде: `импорт: sqlite: cannot start a transaction within a transaction`, повтор каждые 60 с.
- Причина: `apply_upload` (sync.rs:367) оборачивал `import_plu` во внешнюю транзакцию, а `import_plu`/`remove_absent`/`apply_layout` (datastore) сами открывают `unchecked_transaction` — вложенный `BEGIN` запрещён.
- Фикс: внешняя обёртка убрана; каждая операция атомарна сама по себе (sync.rs:366-382).
- Проверка на стенде: `выгрузка (drop): 215 товаров (обновлено 215) … раскладка: 5 групп / 215 переназначено / 0 без группы`.

### D2 (P2) Мусор в выгрузке навсегда блокировал импорт
- Симптом: `/var/ftp/scale/plu.xml: stream did not contain valid UTF-8` (на стенде в файле после валидного XML — 0x96 и обрывок другого документа с собственным `</body>`).
- Причина: `read_to_string`/`String::from_utf8` отвергали весь файл из-за байтов после полезной части.
- Фикс: `decode_xml` обрезает по первому `</body>` (sync.rs:336-346), применяется и к FTP-пути (`fetch_string`), и к drop-каталогу; полностью битый файл по-прежнему отклоняется явно.
- Тесты: `xml_with_trailing_garbage_after_body_is_accepted`, `xml_fully_broken_encoding_is_rejected` (sync.rs).

### D3 (P2) Дедлок регрессионного теста весов
- `fake_scales_recover_after_silence`: после `stop.store(true)` поток мог ждать на gate внутри `poll_once` — `join()` висел.
- Фикс: перед остановкой gate открывается (`max = u32::MAX`, `notify_all`), тест завершается быстро и детерминированно.

### Результат анализа существующей логики
Дефектов P0/P1 в устойчивости весов и принтера не найдено — уже реализованные механизмы (reconnect-цикл весов, Monitor принтера с двойным подтверждением, reopen порта, BUSY, таймауты subprocess) покрывают сценарии отказа; в этой волне они закреплены регрессионными тестами.

## 5. Ограничения
- Ручные проверки сценариев 1, 5, 7, 8 на реальном железе не выполнялись в этой сессии (код-пути покрыты тестами и не менялись).

- Автоповтор заданий печати с неизвестным физическим результатом по-прежнему запрещён (принцип волны 3).
