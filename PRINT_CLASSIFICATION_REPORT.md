## 2. Исправленная ветка

**Fault L4 во время печати.** Было: `Fail::Printer` → ok=0 («достоверная ошибка»).
Ошибочно: байты задания уже отправлены; авария (конец ленты, крышка) могла произойти
после того, как этикетка вышла полностью или частично. Само по себе отсутствие этикетки
в лотке не доказывает отсутствия печати (частичная печать, застрявшая этикетка).
Стало: `Fail::Uncertain` → ok=NULL, оператору — сообщение о непроверенном результате.
Текст причины сохранён («авария принтера во время печати (L4 = …)») — подробности в логе.

Отказы до отправки остались достоверными ok=0: порт не открылся, ESC @ не прошёл,
статус-проверка до отправки выявила аварию (байты не отправлялись), отмена/устаревание.
Протокол, тайминги (present_wait, FAULT_CONFIRM=2, PRINT_TIMEOUT=30 с) не менялись.

Также семантика маркировки вынесена в чистую функцию `outcome_mark(&Result<(), Fail>) ->
Option<bool>` (daemon её использует): Some(true/false) — маркировать, None — оставить
NULL. Поведение идентично волне 14, кроме исправленной ветки fault-при-печати.

## 3. Тесты (полный набор 224 passed, 0 failed)

Новые:

  (порт не открылся) → ok=0; Printer (отказ статуса до отправки) → ok=0.
- `outcome_mark_post_send_failures_are_unknown`: ошибка записи → NULL; fault после
  начала отправки → NULL; отсутствие подтверждения выдачи → NULL.

Уже покрывают остальное (волны 14 и ранее):
- `interrupted_print_stays_unknown_after_reopen` — NULL сохраняется после переоткрытия
  БД (перезапуск);

- `sales_count_ignores_unknown_and_reprints` — отсутствие двойного учёта продаж;
- S15 — отсутствие автоматического повтора: повторный вызов подтверждения во время
  печати игнорируется, новой операции нет; автоматических retry в daemon нет (после
  отказа демон переходит к следующему заданию, повтор — только действие оператора);
- S8/S16/S17 — три сообщения оператору и предупреждение о дубликате при повторе `?`;
- S1–S17, N1–N4 — без регрессий.
