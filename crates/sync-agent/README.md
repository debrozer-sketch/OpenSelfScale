# sync-agent

Приём данных от центра: манифест + sha256 + атомарная публикация.

Замена старого конвейера (lftp-mirror → rsync → флаги uploading.flg/ready.flg),
в котором были гонки, полуразлитые наборы и молчаливые отказы
(см. `audit/PROBLEMS.md` Б2-Б5).

## Инварианты

1. Приложение видит каталог `current` только после полной проверки хэшей.
2. Битая выгрузка никогда не публикуется (verify до publish).
3. Неудачная публикация откатывается к предыдущему набору (backup-переименование).
4. Флаговых файлов нет: манифест с версией — единственный маркер.

## Транспорт

Сетевой слой (HTTPS/SFTP/MQTT) — выше этого крейта; здесь только инварианты
`staging → verify → publish` с полным покрытием тестами, включая сценарий
«вторая выгрузка битая — current не портится».
