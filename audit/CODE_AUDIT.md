## КРИТ — чинить немедленно

1. **print.rs:62-63 — ложная дата на каждой этикетке.** Дата и время зашиты константами из дампа прототипа (`"01.09.26"`, `"10:31:53"`). Печать боевого пути. Надо: фактическая дата/время системы + срок годности из `shelflife` (он уже выбирается в lookup, но в кадр не идёт).
2. **reg_item.ps1:4 — пароль `REMOVED` открытым текстом.** При git init попадёт в историю навсегда. Вычистить до первого коммита; пароль — в .env.
3. **main.rs:1298-1310 — гонка многократной печати.** Сентинел «печать не запущена» = `print_weight_g == 0`. Если вес обнулился между подтверждением и тиком (100 мс), `weight_g = 0` остаётся сентинелом → новый поток печати каждый тик → стопка этикеток «0.000 кг». Фикс: `Option<u32>` + отказ печатать нулевой вес.
4. **main.rs:821, 1168 — фильтр товаров отдела по устаревшему сиду.** Тап по отделу и refresh фильтруют через `datastore::dept_of(g)` (статический SEED_GROUP_DEPT), а плитки отделов строятся по БД-карте `group_dept`. После `--group-assign`/переназначения состав отдела в меню и при входе расходится — товары «пропадают». Фильтровать по карте из БД.
5. **main.rs:1150-1154 — ошибка БД опустошает каталог.** В refresh_data `load_all()/depts_list()/group_depts().unwrap_or_default()`: транзитная блокировка БД (фоновый sync держит соединение) молча превращается в пустой каталог в памяти до следующей синхронизации. Фикс: при Err — не трогать модели, логировать.
6. **Нет git.** Единственная копия состояния — файловая система + живая весы. Откатов нет, непонятно, какой бинарь на весах. Инициализировать после чистки корня (см. ниже).

## Баги (важные)

- **weight.rs:140-169 — Timeout = «порт умер».** Любой Err от `poll_once` → break → переоткрытие tty + 3 с паузы. Весы, отвечающие не на каждый кадр, заставляют порт дёргаться постоянно. Фикс: Timeout обрабатывать как «нет данных», не переподключаясь.
- **shtrih-m:142-169 — параметр `timeout` игнорируется** (`let _ = timeout;` в обеих ветках); в не-unix ветке цикл читает до полного 64-байтного буфера — лишний блокирующий read на каждый опрос, частота опроса вдвое занижена.
- **escpos:82-85 — `double_height` даёт 2×2.** `ESC ! 0x01` — это шрифт B (двойная высота — бит 4, 0x10), `GS ! 0x11` — увеличение по обеим осям. «Двойная» цена печатается шрифтом B и растянута и по ширине. Сверить с дампом, исправить байты или переименовать параметр.
- **sync.rs:163-177 — остывание картинки по одному замеру mtime.** Медленно дописываемый файл (последняя запись >2 с назад, но ещё открыт) копируется битым и навсегда остаётся в `img/plu` (дальше skip по exists). Фикс: два замера размера, как для plu.xml.
- **sync.rs:222-229 — ошибки удаления файлов глушатся** (`let _ = remove_file`). Залипший ready.flg → цикл ошибок «plu.xml не появляется» каждые 5+60 с. Хотя бы логировать неудачу.
- **shtrih-m:79-85 — LRC проверяется раньше длины кадра.** Обрезанный кадр даёт невнятную ошибку вместо честной. Порядок: длина → `:` → LRC → парсинг.
- **main.rs:1017-1043 — `on_more`/`on_back` с экрана 3 (поиск) попадают в ветку отделов** и молча выбрасывают на главный. Либо скрыть пейджер на экране 3, либо ветвить.
