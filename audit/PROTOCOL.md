# Протоколы весов 172.32.0.5 — живой дамп (strace)

Источник: `/tmp/scales_io.trace` с работающего приложения, снят strace-ом
во время 3 взвешиваний с печатью. Локальная копия: `audit/artifacts/scales_io.trace`.
Оба порта открыты одним процессом (fd 11 = /dev/ttyACM0=/dev/scales,
fd 13 = /dev/ttyS3 = принтер).

## 1. Весы: Штрих-М, `/dev/scales`, 115200 8N1

### Цикл опроса (безостановочный, ~каждые 0.5–1 с)
```
→ STX '5' ':' '0' '0' '3' '0' LRC        = \x02\x05:0030<   (8 байт)
← ACK                                     = \x06            (может прийти
← STX ... данные ... LRC                    отдельно, приложение дожидается)
→ ACK                                     = \x06
```

### Кадр ответа (14 байт от STX до LRC; подтверждено живым замером на Debian 13)
```
\x02 \x0b ':' \x00 <status> \x00 <масса:4 байта LE32, знаковая> \x00 \x00 \x00 <LRC>
```
Управляемые байты ACK/NAK приходят ПЕРЕД кадром по одному (могут прийти
отдельными чтениями) и в кадр не входят. NAK (\x15) наблюдается на первый
опрос после открытия порта. После приёма кадра host шлёт ACK (\x06).

- `\x0b` — длина payload (11 байтов после него, LRC вне payload).
- после `:` два константных `\x00`, между ними — статус.
- статус: 0x15 «стабильно», 0x04 «движение», 0x16/0x14 «пусто»;
  «стабильно» = младший бит == 1.
- масса: 32 бита little-endian, ЗНАКОВАЯ: `\x46\x05\x00\x00` = 1350 г,
  `\xfa\xff\xff\xff` = −6 г (дрейф пустой платформы, срезается в 0).

Проверка раскладки: 1350 г — `\x02\x0b:\x00\x15\x00\x46\x05\x00\x00\x00\x00\x00\x67`,
LRC = XOR(0x0B,':',0,0x15,0,0x46,0x05,0,0,0,0) = 0x67 ✓.
Пустая платформа (−6 г) — `\x02\x0b:\x00\x14\x00\xfa\xff\xff\xff\x00\x00\x00\x20`,
LRC = 0x20 ✓ (живой замер, 2026-10).

### Контрольная сумма (подтверждено в обе стороны)
**LRC = XOR всех байтов кадра после STX (не инвертируется).**
- Запрос: `\x05 ^ ':' ^ '0' ^ '0' ^ '3' ^ '0'` = 0x3C = `<` ✓
- Ответ: XOR байтов от `':'` до последнего байта данных включительно ✓

### Практические выводы для драйвера
- Обмен master-slave, таймаут ответа ~1 с; NAK/ACK и кадр приходят отдельными
  чтениями — собирать поток байтов и вырезать кадр от STX по байту длины.
- serialport-крейт на musl-сборке выставляет скорость через BOTHER — устройство
  молчит; порт открывать напрямую через libc termios (см. app/kiosk weight.rs).
- Опрос непрерывный: UI получает вес из фонового потока (weightChanged).
- Всё общение — ASCII-печатные байты + управляющие: логирование и отладка просты.

## 2. Принтер: ESC/POS, `/dev/ttyS3`, 19200 8N1

Полная последовательность одной этикетки (снята 3 раза, идентична):

### Инициализация (на этикетку)
```
ESC t \x11      кодовая страница 17 (в прошивке = CP866; «В» в дампе = 0x82)
FS  c 0 \x01
ESC { \x01      разворот 180° выключен
FS  L           вход в PAGE MODE
FS  T \x02      печать page mode, направление 2
FS  W 0,0,448,232   область этикетки 448 x 232 точки (label width=480,
                    labelFormat=1 — фактическая печать чуть уже)
CAN \x18        отмена предыдущих данных страницы
ESC 3 \x00      межстрочный интервал 0
ESC SP \x00     межсимвольный интервал 0
```

### Каждое поле = пара команд позиционирования + текст
```
ESC ! n / GS ! n   шрифт/размер (двойная высота для цен: ESC ! \x01)
ESC $ xL xH        горизонтальная позиция (X)
GS  $ yL yH        вертикальная позиция (Y, page mode)
<текст в CP1251>   «ВИНОГРАД КИШМИШ ЧЕРНЫЙ КГ», «1,350», «199,99», «269,99»…
```
Наблюдённые Y: 0x40,0x64,0x73,0x86,0x94,0xA0,0xB4,0xD6 (двух-высотные поля
на 0x86/0xD6 — цены/итог).

### Штрихкод
```
GS k \x02 '210213601350' \x00    EAN-13, 12 цифр + NUL
ESC h/GS h — высота, ESC H/GS h HRI...
```

### Завершение
```
ESC ! / GS ! сброс размера, FS { ... , затем \x0C (FF) — печать и выдача
```

### Выводы
- label.xml **напрямую** транслируется в пару (ESC $, GS $) на каждое поле —
  визуальный редактор нового ПО может рендерить 1:1 как на экран (canvas),
  так и на принтер.
- Кодировка CP866 (code page 17; байты дампа: В=0x82, И=0x88 — таблица CP866,
  не CP1251) — новый редактор шлёт text в CP866 или переключает ESC t.
- Параметры из conf соответствуют командам: backwardSpace → откат после FF,
  optoThermoSpace → FS-геометрия, disableStatusCheck → пропуск чтения статусов
  (см. PROBLEMS.md А1/А2).
- 19200 бод на этикетку с графикой — узкое место; скорость порта менять
  осторожно (настройка и на весах, и в принтере).

## 3. Чек-лист сверки для драйвера нового ПО
- [ ] Биты байта состояния весов (0x16/0x15/0x04) — по документации Штрих-М.
- [ ] Команда обнуления (setZero) — запрос не снят в этом дампе (нужен дамп
      в момент нажатия обнуления/сервиса).
- [ ] Поведение при перегрузе/отрицательном весе (статусные биты).
- [ ] Загрузка логотипов (loadLogos) — отдельная процедура, в дамп не попала.
